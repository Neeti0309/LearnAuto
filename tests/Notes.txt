Why would you use headed mode vs headless mode?"

"Headed mode is for debugging — actually watching the browser to understand what's happening. 
Headless is for CI/CD and everyday runs, since it's faster with no UI rendering overhead. 
In practice, most automated pipelines run headless."
-----------------------------------------------------------------------------------------------------
What happens if you reference a fixture in a test without destructuring it?"

"JavaScript throws a ReferenceError — Playwright fixtures aren't globally available, 
they only exist inside a test/hook if you explicitly request them by name in the function's parameters."

--------------------------------------------------------------------------------
Why not just run everything, every time?"
"Because feedback speed matters during active development — a 5-minute smoke check tells 
a developer immediately if they broke something obvious, without making them wait 20 minutes 
for a full regression run on every single commit. The full suite still runs, just at a point 
where thoroughness matters more than speed — before merging."

The real-world standard (not just theory)

Most professional teams use a layered approach, not an all-or-nothing choice:

Trigger	                        What runs	                Why
Every push to a branch	        @smoke only	            Fast feedback (~seconds), catches obvious breakage immediately
Pull request into main	        Full suite	            Before code merges, you want maximum confidence — speed matters less here
Scheduled (e.g. nightly)        Full suite	            Catches flaky/environment issues even when no one's actively pushing
